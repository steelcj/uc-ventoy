## Decisions

- **`sudo_nopasswd` skips comment lines.** The kickoff says "any file contains", the contract says "any sudoers rule contains". The contract wins: a commented `NOPASSWD` is not a rule. Every file in `/etc/sudoers.d` is read, including those sudo skips, and `/etc/sudoers-rs` too.
- **A value that cannot be measured fails the report** with exit status 2, as the kickoff asks for a missing host key. The same applies to an unreadable sudoers file and to an sshd configuration that cannot be read, because a guessed `false` for `sudo_nopasswd` or `ssh_password_auth` would mislead ingress. Exit statuses 0 and 1 keep their meaning.
- **`sshd -G` first, `sshd -T` as the fallback** for `ssh_password_auth`, as for `ssh_port`. The contract names `sshd -T`, which fails on Ubuntu until `/run/sshd` exists, found in the session of 2026-11-15. Both print the same settings.
- **No change for `timestamp` and IPv6 addresses**, which YAML 1.1 parsers also retype. The kickoff asked only for `mac` and `machine_id`. Both are recorded as observations for uc-contracts.

### What the targets do, from their packages

Every package below was downloaded to a temporary folder and unpacked or read. Nothing was installed.

- **sshd.** The stock `sshd_config` of openssh-server 1:10.0p1-7+deb13u4, 1:9.6p1-3ubuntu13.20 and 1:10.2p1-2ubuntu3.8 has `Include /etc/ssh/sshd_config.d/*.conf` as its first setting, and none ships a file in `sshd_config.d`. Each target's own `sshd -G`, run on the stock file with the raw node drop-ins and a `50-cloud-init.conf` saying `PasswordAuthentication yes` and `KbdInteractiveAuthentication yes`, printed `no` for both, `no` for `permitemptypasswords`, `permitrootlogin no` and `pubkeyauthentication yes`.
- **Subiquity** 24.04.5 and 26.04.1 pass cloud-init `users: [{name, lock_passwd: false, ssh_authorized_keys}]`, with no `sudo` key and without `default`, and `ssh_pwauth` from `allow-pw`. `allow-pw` defaults to `not authorized_keys`. Both also have cloud-init write `/etc/cloud/cloud-init.disabled` at the end of the first boot.
- **cloud-init** 25.1.4, 26.1 and 26.2 write a sudoers rule only for a user with a `sudo` key. `set_passwords` writes `PasswordAuthentication no` for `ssh_pwauth: false`, into `50-cloud-init.conf` when `sshd_config` includes `sshd_config.d`. `users_groups`, `ssh` and `set_passwords` run in the init stage, which is `cloud-init.service` (`cloud-init init`) in the 24.04 packages and `cloud-init-network.service` in the 26.04 package.
- **sudo.** The stock `/etc/sudoers` and `/etc/sudoers.d/README` of sudo 1.9.16p2-3+deb13u2 and 1.9.15p5-3ubuntu5.24.04.4, and of sudo-common 1.2ubuntu on 26.04, contain no `NOPASSWD` or `!authenticate`. The example files under `/usr/share/doc` do. sudo-rs 0.2.13 reads `/etc/sudoers-rs` when it exists and `/etc/sudoers` otherwise. Its postinst only creates `/etc/sudoers.d`.
- **Debian host keys.** openssh-server's postinst creates the RSA, ECDSA and Ed25519 keys at install time. `sshd-keygen.service` runs `ssh-keygen -A` only on a first boot.
