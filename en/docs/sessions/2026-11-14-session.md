# Session record, 2026-11-14

This is a record of the session, not current documentation. Where it and the documents disagree, the documents win.

## Outputs

- The combined Debian and Ubuntu document, reviewed and corrected from 0.1.0 to 0.1.2, then split at 0.2.0 into a raw node baseline and one document per target. The 0.3.0 set in this directory aligns them with the generator.
- The generator: `raw-node-input.yml` (four values), `bin/build`, `bin/check-isos`, templates under `debian/13`, `ubuntu/24.04` and `ubuntu/26.04`, and the shared files under `shared/`.
- Download and verification steps for the Debian and Ubuntu ISOs, now in [iso-downloads.md](../iso-downloads.md).

## Decisions

- Ventoy only carries answer files. The answer files build a deliberately small raw node, and Ansible owns the definitive state, including the firewall. Rule: if Ansible would have to manage a setting anyway, it does not belong in the answer file.
- The bootstrap `nftables` firewall stays in the answer files, because raw nodes start with SSH password authentication. Ansible replaces it with Foomuuri.
- Inputs are reduced to four values: two password hashes, the initial user name and one SSH public key.
- Hostnames are `<prefix>-vt` from the target folder, with the last four MAC digits of the default-route interface appended at first boot, for example `deb13-vt-a1b2`.
- Each node writes `confirmation.yml` at first boot: hostname, timestamp, IPv4, IPv6, user and sudo, all measured on the node.
- The Debian answer file writes files with readable `printf` lines instead of base64.
- On the stick, `/answer-files` mirrors `/iso`, and `ventoy.json` matches folders rather than ISO filenames.
- ISOs are verified in the local store before copying, never on the stick.
- MAC prefixes are not used to classify nodes as virtual or physical. `systemd-detect-virt` and the DMI vendor are reliable, and Ansible's facts already report both.
- A Debian 13 Incus host variant waits for automated partitioning. Recommended, not yet decided: Debian 13 with Incus 7.0 LTS as the base for a dedicated Incus host.
- The repository is named `uc-ventoy`.

## Notes kept from the session

### Ventoy, Ansible and Foomuuri

Ventoy does not create a firewall. The `nftables` rules come from the preseed and autoinstall files, and Ansible can replace them with Foomuuri. Two things need care: the handover itself, and package versions. Both are now documented in [raw-node-baseline.md](../raw-node-baseline.md#handover-to-ansible), together with the ordered cutover.

Further points from the discussion:

- Foomuuri should coexist with Docker or Incus better than the bootstrap file, because it is understood to manage its own table rather than flush everything. This was not confirmed against the Foomuuri documentation, so check `nft list tables` after it starts.
- On servers, skip `foomuuri-firewalld` and the D-Bus service, which is where the 2025 CVEs were. On a Mint desktop, `foomuuri-firewalld` is the useful part, and Mint's `ufw` should be removed.
- The name is Foomuuri, with an "i" at the end ("muuri" is Finnish for wall).

### Ubuntu 24.04.5 as a Mint 22 base

24.04.5 is a suitable base for a Mint 22 desktop, and the best 24.04 ISO to use. Point releases only refresh the installation media, and Mint 22.3 runs on the same `noble` archive. Ubuntu 24.04 standard security maintenance runs until May 31, 2029. The adjustments for the desktop layer are in [ubuntu-24.04.md](../ubuntu-24.04.md#use-as-a-linux-mint-22-base).
